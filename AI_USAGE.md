# AI Usage Documentation

## Overview - David
This document outlines the usage of an AI assistant (Google Gemini) in the development of the EMG (Electromyography) Machine Learning classification pipeline. The AI was utilized for conceptual clarification, algorithm design, code generation, and debugging.

## Key Areas of AI Assistance

### 1. Conceptual Understanding & Machine Learning Theory
* **Data Splits:** Clarified the distinct roles of Training (learning), Validation (hyperparameter tuning), and Testing (final unseen evaluation) sets. Explained the critical concept of "Data Leakage" and how to prevent it.
* **Cross-Validation:** Assisted in transitioning from a standard Leave-One-Group-Out (LOGO) cross-validation to a custom Monte Carlo Cross-Validation loop (8-Train, 2-Validation, 2-Test) to better assess model robustness across different participants.
* **Algorithm Mechanics:** Explained the fundamental differences between "lazy learners" (like KNN, which do not update internal math weights during training) and "iterative learners" (like SVM, which optimize hyperplanes).

### 2. Signal Processing & Data Preprocessing
* **Windowing Strategies:** Identified the "Feature Dilution" effect where large 5-second windows average out quick muscle gestures. Advised shrinking the sliding window to 0.25 seconds (250ms) with a 0.05-second step to properly capture peak muscle activations.
* **Normalization:** Emphasized the importance of properly fitting the `StandardScaler` *only* on the training data, and then applying that same transform to the validation and test sets to simulate real-world unseen data.

### 3. Code Generation
* **Model Evaluation Pipelines:** Generated the Python logic for the custom Monte Carlo Cross-Validation loops for LDA, KNN, and SVM. This included logic to catch the "best-performing fold" and automatically plot a Confusion Matrix using `matplotlib` and `sklearn.metrics`.
* **Real-Time Classification Integration:** Wrote `realtime_classifier.py` to bridge the gap between Lab Streaming Layer (LSL) data generated by `myo_interface.py` and the Scikit-Learn models. Implemented a real-time sliding buffer to accumulate exactly 50 samples (250ms) per prediction.
* **Production Serialization:** Authored the script to train final "Production Models" on 100% of the dataset and serialize both the machine learning algorithms (LDA, QDA, KNN, SVM) and the `StandardScaler` into `.pkl` files using `joblib` for deployment.

### 4. Debugging & Error Correction
* Caught a conceptual bug where `y_val` was almost passed to `model.fit()`, preventing a dimension mismatch crash.
* Fixed copy-paste variable errors (e.g., calling `.predict()` on the wrong model instance within a loop).

## Example Prompts Used
* *"Currently my features are RMS, MAV, WL, ZC, Slope Sign Change, Mean Freq, Median Freq, and total power."* (Prompted discussion on feature dilution and scaling)
* *"How would I make a python script that takes the stream from the myo_interface and classifies the grip strength based on its readings?"*

* *"For K Nearest Neighbor, does it need to iterate through multiple times to improve the model based on the validation accuracy?"*
